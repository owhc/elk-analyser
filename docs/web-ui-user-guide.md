# Web UI 操作情境與使用指南

本文檔針對 `ELK Analyser Dashboard` 前端 Web UI（預設入口：`http://localhost:3001`）提供端到端的使用者操作情境、畫面功能說明與操作步驟指南。

---

## 1. Web UI 介面架構與佈局總覽

ELK Analyser 提供沉浸式深色 Morandi 科技風儀表板，主要區分為以下五大功能區塊：

```
┌────────────────────────────────────────────────────────────────────────┐
│ 品牌列 (Brand & Status) │ API 連線狀態 (API 正常/異常) │ 倒數與最後更新時間 │
├────────────────────────────────────────────────────────────────────────┤
│ 關鍵指標卡片 (KPI Row)                                                 │
│ [分析任務總數]       [失敗任務]         [成功完成]         [執行中任務]     │
├───────────────────────────────────┬────────────────────────────────────┤
│ 服務健康檢查 (Service Health)     │ 隨選分析面板 (On-Demand Analysis) │
│ • ELK Analyser API (連線與延遲 ms)│ • 開始時間 (datetime-local)        │
│                                   │ • 結束時間 (datetime-local)        │
│                                   │ [▶ 立即分析]                      │
│                                   │ [⚡ ELK + Instana 合併分析]        │
│                                   │ [注入 Demo 資料]                  │
├───────────────────────────────────┴────────────────────────────────────┤
│ 分析任務紀錄與管理 (Jobs Table & Batch Actions)                        │
│ [全選]  #  | 查詢視窗 | 事故狀況與衝擊 | 狀態 | 診斷報告下載           │

└────────────────────────────────────────────────────────────────────────┘
│ 任務側邊詳情抽屜 (Detail Drawer)                                       │
│ 點擊任一任務開啟：完整事故狀態、根因分析、事件因果鏈、影響範圍與改善建議│
└────────────────────────────────────────────────────────────────────────┘
```

## 2. 使用者操作情境（User Scenarios）

### 情境 A：日常監控與系統健康確認
- **目標**：確認分析平台與後端服務連線狀態及整體歷史分析成功率。
- **操作步驟**：
  1. 開啟瀏覽器進入 `http://localhost:3001`。
  2. 觀察頂部導航列的 **API 狀態燈號**（綠燈：`API 正常`；紅燈：`API 異常`）。
  3. 檢視 **關鍵指標（KPI Cards）**：
     - 確認累計任務數、失敗任務數與成功產出報告數。
  4. 檢視 **服務健康監控卡片**：查看 API 延遲毫秒數（Latency）。
  5. 頂部與底部設有 30 秒自動倒數更新機制，亦可點擊頁尾 `↺ 全部重新整理` 立即手動同步最新狀態。

---

### 情境 B：快速注入展示資料並驗證管線（One-Click Demo Injection）
- **目標**：在無真實線上異常時，快速注入模擬故障日誌並觸發端到端分析。
- **操作步驟**：
  1. 在 **隨選分析面板** 中，可選擇自訂時間，或直接留空（預設會代入 `2026-01-15 08:00` 至 `09:00` 示範視窗）。
  2. 點擊按鈕 **`注入 Demo 資料`**。
  3. 觀察按鈕狀態變為 `注入中…`，下方出現即時反饋文字：`Demo 資料注入完成，分析已觸發`。
  4. 任務列表會自動重新整理，新增一筆任務並即時呈現分析完成狀態。

---

### 情境 C：指定時間範圍執行純 ELK 日誌分析
- **目標**：針對 Elasticsearch 內特定時段的服務日誌進行日誌萃取、事件鏈重組與 AI 診斷。
- **操作步驟**：
  1. 在 **開始時間 (`from-time`)** 與 **結束時間 (`to-time`)** 輸入框選擇欲排查的時間區段（例如：`2026-09-15 08:00` 至 `2026-09-15 12:00`）。
  2. 點擊按鈕 **`▶ 立即分析`**。
  3. 系統將鎖定按鈕並顯示 `分析中…`（背景向 `/api/analyse` 送出請求）。
  4. 分析完成後，下方反饋區提示：`分析完成：異常 N 筆，CRITICAL M 筆`。
  5. 任務列表會自動更新，列出本次產生的分析任務。

---

### 情境 D：執行 ELK + Instana 混合 APM 關聯分析
- **目標**：同時拉取 Elasticsearch 系統日誌與 Instana APM 呼叫鏈（Traces、Metrics、Erroneous Calls），產出包含 APM 視圖的完整報告。
- **建議輸入之實際時間範圍**：
  - **模式 1：靜態 Mock / 展示資料集（離線測試推薦）**
    - **開始時間 (`from-time`)**：`2026-01-15 08:00`
    - **結束時間 (`to-time`)**：`2026-01-15 09:00`
    - *說明*：此時段與 `sample_logs.json` 及 `gen_fake_data.py` 預設產生的 31 筆異常事件鏈（包含 PostgreSQL、WebSphere Liberty 與 IBM MQ 故障）完全重合，且具備 Instana 收集 fallback 資料，必能產生具體分析結果。
  - **模式 2：即時動態事故注入（Live Observability Incident）**
    - 若剛剛剛執行過 `scripts/generate-observability-incident.sh` 或 `scripts/simulate-banking-journey.sh`：
    - **開始時間 (`from-time`)**：當前時間往前 15 分鐘（例如當前為 `14:30`，填入 `2026-09-16 14:15`）
    - **結束時間 (`to-time`)**：當前時間往後 5 分鐘（例如填入 `2026-09-16 14:35`）
    - *說明*：涵蓋實體容器最新產生的 Java HTTP 400 呼叫、PostgreSQL rollback 與 synthetic 異常日誌。
- **操作步驟**：
  1. 在隨選分析面板中，依上述建議填入 **開始時間**（如 `2026-01-15T08:00`）與 **結束時間**（如 `2026-01-15T09:00`）。
  2. 點擊按鈕 **`⚡ ELK + Instana 合併分析`**。
  3. 按鈕變更為 `Instana 收集中…`，系統在背景調用 Instana Collector 同步收集 APM 遙測數據。
  4. 成功後反饋：`ELK + Instana 合併分析完成：異常 N 筆，CRITICAL M 筆`。
  5. 產出的分析報告將包含 Instana 關聯遙測分析與對應投影片頁面（Slide 3.5）。

---

### 情境 E：檢視事故詳情抽屜與 AI 根因推論（Detail Panel）
- **目標**：在不下載報告的情況下，直接於 Web 介面瀏覽 Bob AI 診斷之根本原因、因果鏈與處置建議。
- **操作步驟**：
  1. 在任務列表中，找到目標任務列並點擊任一行（支援滑鼠點擊或鍵盤 `Enter`/`Space`）。
  2. 畫面右側滑出 **任務詳情抽屜（Detail Panel）**。
  3. 詳情面板內容包含：
     - **任務資訊**：任務 ID、觸發模式（如 `webui`、`webui_instana`）、查詢時間視窗、執行狀態。
     - **事故狀態與嚴重層級**：事故標題、嚴重等級標籤（`CRITICAL` / `HIGH` / `MEDIUM`）。
     - **根本原因分析（Root Cause）**：Bob AI 診斷的核心原因摘要。
     - **衝擊分析（Impact Analysis）**：客戶衝擊、業務衝擊與受影響服務清單。
     - **事件因果鏈（Event Chains）**：依時序排列的跨服務呼叫與異常事件推進鏈。
     - **改善與修復建議（Recommendations）**：短中長期行動方案。
  4. 點擊右上角 `✕` 按鈕、按 `Esc` 鍵或點擊遮罩外側即可關閉面板。

---

### 情境 F：下載 PPTX 診斷簡報與匯出
- **目標**：下載由 Report Builder 產出的專業主管級 PPTX 診斷報告。
- **操作步驟**：
  1. 在任務列表中，找到狀態為 `completed` 的任務。
  2. 在最右側「報告」欄位，點擊 **`↓ 下載`** 連結。
  3. 瀏覽器將自動下載對應之 `.pptx` 檔案（例如：`report-job-1.pptx`）。

---

### 情境 G：任務選取與批量管理（Batch Management）
- **目標**：批次刪除過期或無效的歷史分析紀錄。
- **操作步驟**：
  1. 勾選各任務列左側的核取方塊（Checkbox），或點擊表頭的 **全選核取方塊**。
  2. 表頭上方即時彈出 **批量操作工具列**，顯示 `已選 N 筆`。
  3. 若需放棄選取，點擊 `取消`；若確認清除，點擊 **`刪除所選`**。
  4. 系統將發送批次刪除請求並自動刷新任務列表與 KPI 指標數據。

## 3. Web UI 與後端 API 對照參考

| Web UI 操作 / 元件 | 對應後端 REST API 端點 | HTTP Method | 備註說明 |
|---|---|---|---|
| 頁面載入 / 倒數重新整理 | `/api/jobs?limit=20` | `GET` | 取得最新任務紀錄並計算 KPI |
| 服務健康狀態檢測 | `/api/health` | `GET` | 取得 API 與核心組件健康度 |
| 點擊「立即分析」 | `/api/analyse` | `POST` | 傳入 `from_time` 與 `to_time` |
| 點擊「ELK + Instana 合併分析」 | `/api/analyse` | `POST` | 傳入 `trigger: "webui_instana"` |
| 點擊「注入 Demo 資料」 | `/api/demo/inject` | `POST` | 傳入 `trigger_analyse: true` |
| 點擊任務列開啟詳情 | `/api/jobs/{id}` | `GET` | 取得該任務完整 JSON 診斷資料 |
| 點擊「下載」報告 | `/api/jobs/{id}/report` | `GET` | 下載產出之 PPTX 簡報檔案 |
| 批次「刪除所選」 | `/api/jobs` | `DELETE` | 批次或單筆刪除歷史紀錄 |
